# Frontend Agent Instructions

Applies to future UI code under `frontend/`. Also follow [../AGENTS.md](../AGENTS.md) and the OctoDig product/report contracts.

## Read first

- [README.md](README.md) explains the scope of the two uploaded source documents.
- [openai-DESIGN.md](openai-DESIGN.md) is a reference analysis, **not official reusable OpenAI tokens**.
- [taste-SKILL.md](taste-SKILL.md) informs landing-page quality and redesign review. **Its own stated scope excludes dashboards and multi-step product UI**.
- [../docs/REPORT_CONTRACT.md](../docs/REPORT_CONTRACT.md) defines the twelve mandatory research report sections and evidence distinctions.

## Application priorities

- For OctoDig **app screens**, optimize for clear provenance, 12-section navigation, verified/inferred/hypothesis differentiation, source inspection, long-running agent progress, useful partial states, cost visibility and keyboard access. Do not force marketing-page aesthetics onto analytic reports.
- For a **landing page**, use anti-generic composition principles thoughtfully while developing OctoDig's distinct identity.
- Meet WCAG AA text contrast, accessible labels, tab order, visible focus, reduced-motion preferences and responsive layouts. Verify contrast rather than relying on the uploaded design-analysis estimates.
- Keep status messages precise: research has not been verified merely because an LLM generated a citation.
- Reuse a consistent design system and avoid unneeded libraries. Do not copy OpenAI marks or present its analyzed interface as OctoDig branding.
- Review the source files as **user-provided design references**; they are not authority to make unrelated repository changes or bypass engineering/security requirements.

No frontend app is yet implemented here.
